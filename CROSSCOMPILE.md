## Windows

🙏🙏🙏

Windows releases are built from macOS or Linux with [cargo-xwin](https://github.com/rust-cross/cargo-xwin). The whole pipeline is scripted, so you don't have to remember the flags.

```sh
python3 scripts/build_windows.py
```

Output:

- `target/x86_64-pc-windows-msvc/release/umbrage.exe`
- `dist/umbrage-windows/` portable folder (exe + Qt runtime)
- `dist/umbrage-setup.exe` NSIS installer

Flags:

- `--clean` wipes the Windows target before building
- `--skip-installer` stops after assembling the portable folder
- `--skip-payload` only compiles the exe
- `--qt-root` changes where Qt is installed (default `~/Qt`)
- `--qt-version` changes the Qt version (default `6.10.3`)

### Prerequisites

- Rust with the MSVC target: `rustup target add x86_64-pc-windows-msvc`
- `cargo-xwin`
- `llvm` and `lld`
- `makensis`
- Python 3.10 or newer
- `aqtinstall`. The script installs it into `~/.cache/umbrage-cross/venv` when `aqt` isn't on `PATH`.

### How the cross build works

A few things in this pipeline are easy to get wrong, so the script handles them.

**Qt versions must match.** The script installs Windows Qt `6.10.3` (`msvc2022_64`) for the target and host Qt `6.10.3` for the build tools. The tools produce target-independent output, but `rcc` changed its default compression. Qt 6.11 writes zstd, and Qt 6.10.3 refuses to register those resources at runtime. `QResource::registerResource` returns false, and every QML module under `qrc:/` disappears with a "module X is not installed" error. Keep the host and target versions aligned.

**qtbridge finds Qt through qmake/qtpaths.** The script writes shims that report the Windows Qt headers and libraries for the target, but the host Qt `moc` and `rcc`. It then points `QMAKE` at the qmake shim and `RCC` at the host rcc.

**cargo-xwin supplies the MSVC toolchain.** It downloads the MSVC headers and import libraries and links with `lld-link`. Qt ships MSVC import libraries, so the `x86_64-pc-windows-msvc` target is required. MinGW cannot link against them.

### Qt Quick Controls style

The style is set in `src/ui/qtquickcontrols2.conf`, which is embedded in `resources.qrc`. Keep it there. Do not set `QT_QUICK_CONTROLS_STYLE` from Rust. On Windows, Qt reads the CRT environment while `std::env::set_var` updates the Win32 environment block, so Qt never sees the variable and falls back to the native Windows style, which then rejects the custom `background` items in `UButton` and `ModalDialog`.

### Installer

`dist/umbrage.nsi` is generated by the script. It installs to Program Files, adds Start Menu and desktop shortcuts, writes the uninstall entry, and flags the exe to always run elevated because WinUSB access needs administrator rights. The WinUSB/libusb driver itself is not bundled: end users install it manually with Zadig.

### Testing a Windows build

Run the installer on a Windows machine. If the app compiles but exits right away, a Qt DLL or plugin is missing from the payload. QML errors go to stdout, so run it from a terminal to see them.
